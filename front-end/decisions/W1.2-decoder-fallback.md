# W1.2 — Decoder fallback ladder: WebCodecs-first, AAC-only WASM deviation

**Status: DECIDED (documented deviation, user-authorized)** — written 2026-11-12, P1 session.
Defines the decoder backend ladder for the web audio spine and records the deliberate
scope cut on the WASM rung.

## The ladder

```
resolve.ts picks the itag by MACHINE CAPABILITY
  └─ webCodecsAvailable() ? [251 opus, 140 aac] : [140 aac only]
       │
audioDecoder.ts createAudioDecoder(format)
  ├─ rung 1: WebCodecsAudioDecoder  — platform AudioDecoder; Chrome 157
  │           decodes BOTH opus (itag 251 / WebM-Opus, RFC 6716 TOC durations
  │           measured on real streams) and mp4a.40.2 (itag 140 / fMP4, ASC
  │           1210). Probed with isConfigSupported BEFORE committing — the
  │           ladder order is honest at runtime, not hardcoded hope.
  └─ rung 2: WASM (symphonia) — NOT BUILT in P1 (see deviation)
```

## The deviation (authorized)

The P1 task book's WASM rung (crates/streamify-decoder-wasm: symphonia AAC +
isomp4 compiled to wasm) is **not built**. The crates.io finding that forced the
cut: **symphonia-codec-opus does not exist** (as of 2026-11) — symphonia cannot
decode Opus, so a symphonia WASM rung could only ever serve AAC.

Led sign-off (this session): rather than ship a half-capable WASM rung, P1 takes
the **force-AAC** posture — the resolver refuses to hand the spine a codec the
machine cannot decode, and on browsers without WebCodecs that means AAC-only
(itag 140):

* `resolve.ts`: itag preference is `[251, 140]` with WebCodecs, `[140]` without.
  An Opus-only stream on a non-WebCodecs browser resolves to nothing rather than
  to a guaranteed decode failure mid-spine.
* `audioDecoder.ts`: the WASM hook (`tryWasmDecoder`) exists so the ladder shape
  is load-bearing, and throws the typed `NoDecoderError` today. The deviation is
  documented in the factory header, not hidden in a silent path.

## Why this is acceptable for P1 (and what it costs)

* **Chrome is the P1 target** (WebCodecs AudioDecoder shipped in Chrome 94;
  the whole spine — worklet ring, transferable writes, f32 interleave handling —
  is Chrome-tested). The WASM rung exists for Safari/Firefox parity, which is a
  P2+ concern (the sink transport's sample-rate contract and the decoder's
  output-layout handling would both need per-browser verification first).
* **Cost, stated plainly**: a browser without WebCodecs plays AAC streams only.
  YouTube serves itag 140 for effectively all content (the P0 canary matrix and
  this session's licensed probes both always saw it), so the catalog coverage
  loss is near-zero; the quality loss is AAC 128k vs Opus ~130k — immaterial.
* **The escape hatch**: the ladder shape is intact. Building the WASM rung later
  = implement `tryWasmDecoder` with a symphonia-aac + isomp4 wasm crate (or an
  Opus-capable alternative when one lands on crates.io); nothing else in the
  spine changes — the demuxers, transport and worklet are codec-agnostic by
  construction (proven: the same spine played itag 251 WebM-Opus AND itag 140
  fMP4-AAC this session).

## Verification hooks

* WebCodecs rung: the spine's standard-track G1 proof (Playing, 0 underruns,
  `webcodecs:opus` + `webcodecs:aac` both exercised across this session's runs).
* AAC-only posture: `resolve.ts`'s capability-gated itag list + the typed
  `NoDecoderError` path in `audioDecoder.ts`.

# G4.2 — The 9-second wall: SABR stream protection, the broken mint, and the token-first ladder

**Date:** 2026-11-14 · **Branch:** `ws-w/g4-residential-direct` (iterating on #167) · **Extends:** G4-residential-direct.md

## The mandate

After the G4 pivot, the phone (browser, live relay) reported the first
real progress — **songs played from search** — but every licensed track
**streamed for exactly ~9 seconds and then buffered forever**. One
exception ("Taylor Swift – The Fate of Ophelia (Lyrics)",
`lZEf_izPCfY`) played in full. The directive: fix it in this PR.

## The diagnosis (lab + agent-browser, 2026-11-14)

### 1. The tokenless SABR lane was the 9-second wall

The G4 ladder (slot 2, `ios-direct`) accepted the IOS client's SABR-only
outcome — URL-less format descriptors + `serverAbrStreamingUrl` — as a
playable stream. Replicated outside the browser (bun + the live relay,
exact browser envelope incl. the Chrome UA):

- POST `rn=0` → **HTTP 200, one unprotected burst of exactly 62,383 B**
  (init + media; ≈ 9–10 s of itag-139 48 kbps AAC — the app's
  `pickAudioFormat` picks the first `audio/mp4`, itag 139).
- Every subsequent POST → **HTTP 200 + `streamProtectionStatus: 2`
  (attestation pending) + ZERO media parts** — 2,000+ empty POSTs per
  minute if unchecked (SabrStream's retry loop does not fail fast).
- Final failure mode varies (`No media parts…` /
  `Player response reload requested by server`), 55–106 s later — the
  element meanwhile plays the one burst and buffers forever.

The lyrics-video exception is fully explained: it is **not Content-ID
licensed**, so `visionos-direct` (slot 1) answered OK with a pre-signed
**progressive itag-140 URL** → the `<audio>` element streams it natively
→ full playback.

### 2. The mint has been dead since the trayride rotation

The BgUtils mint (`potMinter.ts`) failed its **primary snapshot** with
`ReferenceError: webPoSignalOutput is not defined` — before any
attestation ran. Two measured causes in the CURRENT trayride program
family (the programs rotate server-side):

1. An explicit `skipPrivacyBuffer: false` in the snapshot args breaks
   the VM (the flag must be UNSPECIFIED on the primary attempt — kira's
   recipe; `true` only on the Brave-class retry).
2. The current program family reads the signal output from the
   **global scope** — without `globalThis.webPoSignalOutput` set before
   the snapshot, the same ReferenceError fires.

Every "live" mint since the rotation silently degraded to
websafe-fallback/coldstart tokens, so the POT'd rungs never actually
carried real attestation. With both details fixed the mint completes in
**0.2 s** in a real browser (agent-browser, all legs via the relay):
`kind=live`, player token (videoId-bound) + session token
(visitorData-bound).

### 3. PO tokens DO unlock licensed playability — and materially bigger SABR windows

With the fixed mint (all legs via the relay — the same egress every
player call and SABR POST rides; the single-envelope rule):

- `WEB + player poToken` → playability **OK** for 4NRXx6U8ABQ through
  the relay egress (flap-dependent — see below).
- IOS-class SABR with a token: still the 62 KB burst cap (the token
  unlocks playability, not the IOS SABR window).
- **WEB-class SABR** (the kira recipe: deciphered
  `server_abr_streaming_url` + `buildSabrFormat` descriptors + WEB
  `clientInfo` + the videoId-bound poToken): **1,132,396 B** of licensed
  media — ~69 s of itag-140 AAC — then the same protection wall.
- VISIONOS via the relay flaps between OK+URL-ful and LOGIN_REQUIRED for
  licensed content (both observed same-day). A URL-ful verdict is the
  **full-playback** outcome (progressive, element-native).

### 4. What the SABR continuation wall is NOT (all measured, same result: 1,132,396 B)

- Not the egress IP class (sandbox direct ≠ live Cloudflare relay ≠
  local relay — identical byte count).
- Not the Origin/Referer/sec-fetch fingerprint (web-player-fingerprint
  pin on googlevideo POSTs tested via a local relay variant — identical).
- Not the User-Agent (bun vs Chrome — identical).
- Not token reuse (fresh videoId-bound token per request — identical).
- Not the racing downloader playhead (real-time-paced requests with a
  simulated 1× playhead + bandwidth estimate — identical).

The initial window is followed by `streamProtectionStatus: 2` and the
server's UMP dance (context updates → `SabrRedirect` to an edge node →
format init + media → `NextRequestPolicy`). Completing the attestation
handshake past the window is **upstream protocol work** (kira's working
production path is the extension + Shaka-class
`SabrStreamingAdapter`; its proxy mode shares our egress constraints).
Follow-up: adopt the streaming-adapter pattern (per-segment requests
through a real player pipeline) for full-length licensed SABR.

## The fix (this PR)

1. **potMinter** — `globalThis.webPoSignalOutput` exposed before every
   snapshot attempt; `skipPrivacyBuffer` UNSPECIFIED on the primary
   attempt (`true` only on the Brave retry); the WAA legs
   (Create/GenerateIT) route through the relay **always**
   (`waaFetch`) — the single-envelope rule (mint egress == player/SABR
   egress), matching how bgutil-ytdlp-pot-provider and kira keep
   mint-IP == use-IP.
2. **resolve.ts — the token-first ladder**:
   - The PO token mints BEFORE the licensed rungs (once per ~12 h).
   - Rung 1 VISIONOS-direct keeps 3 flap attempts (a URL-ful verdict is
     the full-playback outcome).
   - Rung 2 WEB+POT: progressive (deciphered, `&pot=`-pinned) → HLS →
     **the kira-recipe SABR payload** (the only SABR the ladder accepts).
   - Rung 3 IOS+POT, rung 4 IOS-direct: progressive/HLS only —
     `evaluateRawResponse` rejects SABR-only outcomes on app-client
     envelopes with an honest verdict ("the measured 62 KB burst cap").
   - Rung 5 VISIONOS-relay, rung 6 WEB_SAFARI unchanged.
   - WEB+POT gets the same 3-attempt flap-retry as the raw rungs.
3. **sabrStreamPlayer** — two guards so a walled session can never
   hammer or buffer forever again: a **first-media budget** (8 s, zero
   bytes → abort) and a **no-media circuit breaker** (6 consecutive
   protection-status responses with no new media → abort). One lab run
   measured 2,458 empty POSTs in 60 s through the shared relay — exactly
   the hammering that burns the egress for every other rung.
4. **wasmEngine** — a failed SABR session parks the sink (no infinite
   Buffering spin on the partial burst); the rotation path
   (`onStaleUrl`) never hands the element a SABR placeholder or an HLS
   manifest URL (both are guaranteed media errors) — it ledgers and
   parks honestly, and the user's retry escalates the ladder.
5. **`&pot=` pinning** — progressive googlevideo URLs from the POT'd
   rungs carry the GVS token (`pinGvsPot`, best-effort, never mints).

## The measured outcome (agent-browser, live relay, this branch)

- Standard content (`dQw4w9WgXcQ`): `visionos-direct` itag-140
  progressive — unchanged full playback.
- Licensed (4NRXx6U8ABQ, real app UI, search → play): resolved via
  `web-pot-direct` SABR `pot=live`; **69 s of playback** (0:23 playhead,
  0:46 buffered) before the circuit breaker surfaced the honest error —
  versus the pre-fix 9 seconds + infinite buffering. During healthy
  flap windows VISIONOS answers URL-ful and the track plays in full.
- The mint: PASS in 0.1–0.2 s, `kind=live`, both token classes.

## Honest limits

- Licensed SABR still caps at the initial server window (≤ ~69 s
  observed); full-length licensed playback rides the VISIONOS URL-ful
  windows (flap) until the streaming-adapter follow-up lands.
- The shared relay egress's licensed verdicts remain probabilistic; the
  flap-retry policy maximizes the odds per play, and the circuit breaker
  keeps the app from burning the egress further.

# The Acoustic Embedding Contract, v1

**Status:** ACTIVE — WS-D D1 (AHEAD.md Wave 3, "Taste Engine").
**Owner:** ENG-4.
**Canonical types:** `streamify-core/src/acoustic_embedding.rs` (Rust),
`uniffi.streamify.AcousticEmbedding` (Kotlin/Swift via the UDL record).

## Why a contract

Before WS-D the continuum engine consumed a raw `[f32; 128]` whose layout
was implicit folklore — `vec[0]` meant BPM, `vec[1]` meant artist hash,
and nobody outside the original author's head could prove it. The D1
mandate: a **versioned, named, layout-pinned** embedding so the radio
lane, the daylist lane, the blend lane and the session continuum all
score against one frozen vocabulary.

Identity fields (artist / track hashes) are deliberately **not lanes**:
they travel as explicit arguments (`continuum_commit`'s
`artist_hash` / `track_hash`), never overloaded into vector positions.

## The wire format

```text
[version: 4B u32 LE][dims: 128 × 4B f32 LE]   = 516 bytes exactly
```

Little-endian on every platform (the workspace `wire_le` convention).
`AcousticEmbeddingVector::from_le_bytes` validates:

* the version header is exactly `1`;
* every lane is finite (no NaN / ±inf);
* the `LAYOUT_VERSION` tripwire lane reads `1.0`;
* the reserved lanes `[RESERVED_FIRST, 127)` are zero.

Unknown future versions are **rejected**, never guessed: consumers
parse the version first and dispatch.

## The 128 lanes

| Lane | Field | Domain | Meaning |
|---|---|---|---|
| 0 | `BPM` | 40..=240, 0 = unknown | Tempo estimate (onset-flux autocorrelation) |
| 1 | `CAMELOT_NUMBER` | 1..=12 | Open Key wheel number |
| 2 | `CAMELOT_LETTER` | 0 = A (major), 1 = B (minor) | Wheel letter |
| 3 | `INTEGRATED_LUFS` | −70..=0 | ITU-R BS.1770-4 integrated loudness |
| 4 | `CREST_FACTOR_DB` | 0..=24 | Peak / RMS crest |
| 5..15 | `SPECTRAL_BAND_i` | 0..=1 | 10 octave-band energies against the `StudioEqualizer` centers (31.25 Hz .. 16 kHz), dB-normalized |
| 15 | `SPECTRAL_CENTROID_KHZ` | 0..=12 | Power-weighted spectral centroid |
| 16 | `SPECTRAL_FLATNESS` | 0..=1 | Wiener-entropy flatness (geo/arith mean) |
| 17 | `ZERO_CROSSING_RATE` | 0..=1 | ZCR per sample |
| 18 | `RMS_MEAN` | 0..=1 | Mean amplitude |
| 19 | `DYNAMIC_RANGE` | 0..=1 | P95 − P10 amplitude spread (histogram quantiles) |
| 20 | `ONSET_RATE` | 0..=12 | Detected onsets per second |
| 21 | `BEAT_STRENGTH` | 0..=1 | Normalized flux-autocorrelation peak |
| 22 | `BPM_CONFIDENCE` | 0..=1 | Tempo-estimation confidence |
| 23 | `DANCEABILITY` | 0..=1 | Composite (beat strength, onset rate, tempo comfort) |
| 24 | `ENERGY` | 0..=1 | Composite (RMS, upper-band energy) |
| 25 | `VALENCE` | 0..=1 | Composite (KS major-ness margin, brightness) |
| 26 | `ACOUSTICNESS` | 0..=1 | Composite (inverse flatness, inverse ZCR) |
| 27..91 | `WAVEFORM_i` | 0..=1 | 64 peak-preserving RMS buckets (`waveform_indexer`, 128 buckets max-paired down to 64) |
| 91..127 | reserved | 0 | Zero in v1; additive v1.x growth only |
| 127 | `LAYOUT_VERSION` | 1.0 | The version tripwire |

The schema constants live in `streamify_core::acoustic_embedding::layout`
and are mirrored in the Kotlin and Swift contract suites.

## Cross-language pinning

One golden fixture — `fixtures/acoustic_embedding/v1_reference.bin`
(516 bytes, generated by the ignored Rust test
`write_reference_fixture` after an **intentional** schema change) — is
pinned by three suites:

| Suite | Lane |
|---|---|
| `streamify-core` `acoustic_embedding::tests::golden_fixture_pins_the_layout` | Rust (reads the file) |
| `app/src/test/.../AcousticEmbeddingContractTest.kt` | Kotlin JVM (embedded hex image) |
| `iosApp/Tests/StreamifyIOSTests/EngineTests/AcousticEmbeddingContractTests.swift` | Swift (embedded hex image) |

All three recompute the documented lanes from the schema constants and
compare layout-for-layout. A lane renumbering fails every language at
once — that is the point.

## Version policy

* **Additive v1.x**: new features fill reserved lanes `[91, 127)` and
  must update this doc, the fixture (via the ignored regeneration test)
  and all three suites in the same commit. The wire version stays `1`.
* **Breaking v2**: a lane renumbering ships as a NEW record type
  (`AcousticEmbeddingV2`); `v1::from_le_bytes` keeps rejecting unknown
  versions, so old and new producers coexist across an upgrade window.
* The `AcousticEmbedding` UDL record (the Kotlin/Swift currency)
  carries the headline scalars unpacked (`bpm`, `camelotNumber`,
  `camelotLetter`, `integratedLufs`, `danceability`, `energy`,
  `valence`, `acousticness`) so shells never index lanes by hand.

## The producer (D2)

`streamify-audio/src/embedding_producer.rs` builds v1 vectors from
canonical 48 kHz interleaved stereo `f32` (the playback data plane's
staging-buffer geometry) by composing the three production-grade
primitives: `lufs.rs` (BS.1770-4), `dsp.rs` (the radix-2 FFT engine +
the 10-band `StudioEqualizer` centers) and `waveform_indexer.rs`
(peak-preserving RMS). Pure Rust, zero ML runtime, zero network;
deterministic for a fixed input (the documented ε across platforms is
the last ULP of `sin`/`cos`/`log10`/`sqrt`). Clips longer than 30 s
analyze their first 30 s — the embedding is a pure function of content,
never of feed chunking.

The execution budget (≤ 200 ms per 30 s clip on a mid-range 2020
phone) is proven by the CI benchmark lane
(`_ci-engine.yml` → `embedding-bench`, median-of-21 at release speed;
see `rust/crates/streamify-audio/examples/embedding_bench.rs` for the
headroom derivation).
